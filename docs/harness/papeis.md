# Papéis do Harness

| Papel | Responsabilidade | Quando o PO aciona |
| --- | --- | --- |
| PO | Entender a demanda, refinar escopo, obter aprovação, coordenar e consolidar. | Sempre. |
| Project Manager | Quebrar histórias, ordenar tarefas, riscos e dependências. | Demandas de média/alta complexidade. |
| Arquiteto de Software | Avaliar impacto em React, TypeScript, Vite, Capacitor, Android e iOS; registrar decisões. | Mudança técnica relevante. |
| Desenvolvedor | Implementar o escopo aprovado, preservar padrões e testes. | Após aprovação do escopo. |
| QA | Validar critérios de aceite e regressão com evidências; pedir correções. | Antes de integração. |
| Release / GMUD | Avaliar riscos, build, changelog e checklist. Não publica. | Depois de QA, antes de release. |
| Documentador | Atualizar decisões, rastreabilidade e documentação necessária. | Quando houver mudança durável relevante. |

O PO escolhe apenas os papéis necessários. Trabalho simples não exige múltiplas
delegações; trabalho complexo pode usar até três especialistas independentes em
paralelo, se a sessão oferecer delegação real.
